# 桌宠美术规格

这份规格面向角色设定、逐帧绘制与导出；窗口行为见 [ADR-0014](./adr/0014-desktop-pet.md)，UI 规则见 [`docs/ui-spec.md`](./ui-spec.md) 的桌宠章节。

## 角色

- **原型**：owner 家中的橘猫。必须保留能一眼认出的特征：橘色虎斑、白色口鼻/胸口、粉鼻、眼睛颜色、耳形、尾巴与体型；具体花纹以参考照片为准。
- **比例**：微 Q，约 2.5–3 个头高；头略大、身体和四肢略短，但不是大头娃娃，仍保留猫的体态。
- **风格**：轻写实/绘本风。无粗描边，软阴影，边缘一点轮廓光，脚下很淡的接触阴影；与 `app-icon.svg` 的暖橙/奶油/深棕/粉同族，但不复制图标的几何简化。
- **画布**：设定图 1024×1024；动画帧按 512×512 绘制、导出 384×384。
- **背景**：动画帧完全透明；不画桌面、房间、底座、光圈或文字。

## 参考素材

正式画设定图前需要 owner 提供：

- 5–10 张清晰照片或短视频，尽量覆盖：正面、3/4、侧面、全身、睡姿、脸部特写、尾巴、爪子。
- 有原始视频最好；现有 `splash.gif` 与 `splash.png` 是低分辨率实拍，只能辅助，不足以定花纹和眼睛颜色。
- 需要 owner 确认的特征：眼睛颜色、白手套范围、胸口白毛形状、尾巴花纹、耳朵是否有缺口/疤痕、鼻子颜色、体型偏胖/偏瘦。

## 角色设定图

正式帧之前先冻结一张设定图：

| 内容 | 要求 |
| --- | --- |
| 视图 | 正面、3/4、侧面；同一只猫、同一比例、同一光照 |
| 表情/眼型 | 中性、眨眼、开心（React）、困倦（Sleep） |
| 走路 | 侧/3-4 走路姿态与腿脚循环；一个方向，另一方向水平镜像 |
| 色板 | 主橘、暗橘、奶油白、深棕、粉鼻、眼睛色；给 Hex 值 |
| 关键特征 | 虎斑走向、白口鼻/胸口/爪子、耳形、尾巴、体型 |
| 画布 | 1024×1024，中性灰或浅/深棋盘底，方便检查透明与轮廓 |
| 标注 | 脚底基线、头身比、可动部位（耳/眼/尾） |

- 先出 **2–3 版** 供 owner 选择；选定后修正并冻结，不再同时维护多套比例。
- 设定图冻结后再画 3 帧 Idle 试片；试片通过后才画满 38 帧。

## 动画帧

| 状态 | 帧数 | 逐帧时长 | 说明 |
| --- | --- | --- | --- |
| `idle` | 12 | 100–120ms | 呼吸 + 尾巴轻摆；循环；脚底不滑动 |
| `blink` | 3 | 80ms | 半闭/闭/睁；身体中性；回到当前 Idle |
| `react` | 3 | 80ms | 竖耳、眼睛睁大、轻微弹起；结束回 Idle |
| `drag` | 2 | 150ms | 被拎起的悬垂姿势；拖动时两帧交替 |
| `sleep-in` | 4 | 120ms | 从站/坐到趴下/蜷起；不循环 |
| `sleep` | 4 | 300ms | 趴睡慢呼吸；循环 |
| `wake` | 2 | 100ms | 伸懒腰/站起；回 Idle |
| `walk` | 8 | 100ms | 侧/3-4 走路循环；入场时随窗口路径播放；按方向水平镜像；步幅与路径速度匹配 |

- 合计 **38 帧**（30 帧基础 + 8 帧走路）；约 10fps，逐帧时长由动画清单定义，不按固定帧率取整。
- 爱心、`Zzz` 等是矢量/UI 元素，**不要烘焙进帧**。
- 眨眼只在 `idle` 触发；`react`/`drag`/`sleep` 中不画眨眼。
- 眼睛默认**睁开**：窄杏仁形、可见瞳孔；只有 `blink` 全闭、`sleep` 半闭、`react` 睁大。Idle/walk 不要用「常眯眼」表现。
- `blink` 用中性身体姿态，只有眼睛变化；眨眼时呼吸暂停一瞬是接受的，不做分层的眼睛叠加。
- `sleep` 的呼吸幅度比 `idle` 更小、更慢；`Zzz` 由 UI 叠加，不画在帧上。
- 拖拽姿态要像被轻轻拎起：身体略拉长、四肢自然下垂，不要疼痛或挣扎。
- `walk` 是一个方向的 8 帧循环；内容页入场向右下、屏幕边缘入场向左，按方向水平镜像；步幅要与约 450 px/s 的路径速度匹配，不能出现明显滑步。

## 画布与对齐

- 所有帧同一画布、同一比例；**脚底/身体最低点在同一条水平基线**，建议距画布底边 24px。
- 猫的水平中心对齐画布中心；尾巴、耳朵、爪子可超出中心线，但不得出画布。
- `sleep` 可以更宽、更低，但基线不变；不要为睡着单独换画布。
- 导出的透明边缘不得有黑边/白边；半透明毛发用直通 alpha，边缘做 1–2px 的柔和收边。
- 接触阴影烘焙在帧内，低透明度、椭圆、贴脚底；深色桌面上不能变成一块黑斑。

## 导出

| 项 | 值 |
| --- | --- |
| 格式 | PNG（RGBA，8 位/通道）；不用 GIF/APNG/WebP/JPEG |
| 尺寸 | 384×384 |
| 目录 | `src/JiuMi/Assets/Pet/<state>/`，状态名小写连字符：`idle` / `blink` / `react` / `drag` / `sleep-in` / `sleep` / `wake` / `walk` |
| 文件名 | 两位序号，从 `00.png` 开始；按播放顺序编号 |
| 清单 | 由代码中的动画清单定义帧序与时长；导出时同时给出 `状态 → 帧数 → 时长` 表 |
| 源文件 | PSD/Krita/AI 源文件不进 git；仓库只放导出 PNG |
| 体积 | 38 帧总量目标 ≤ 12MB；超过要在实现票说明并给出优化方案 |

- 导出前删除隐藏图层、背景、参考线、文字；只保留猫本体与接触阴影。
- 每帧独立 PNG，不用雪碧图；Avalonia 侧按状态按需加载。
- 未来加 120/200 DIP 尺寸档位时再出 512 版，不提前塞进 v1。

## 可读性检查

- 在 **160×160 DIP** 下看：脸、耳朵、眼睛、白手套和尾巴仍可辨认；缩小后不糊成一团。
- 浅色、深色、带壁纸的桌面上各看一次：轮廓光能分离深色背景，接触阴影能落在浅色背景上。
- 100% 缩放是验收基线；200% 文本缩放下窗口仍 160 DIP，按 DIP 缩放，不裁切。
- Win10 与 Win11 都看一次透明边缘；任一版本出现黑边/白边都退回修图，不在运行时补丁。

## 审核门

1. **参考素材**齐全，owner 确认特征。
2. **设定图** 2–3 版，owner 选定并冻结。
3. **3 帧 Idle 试片**在 160px、浅/深桌面通过；另做 3 帧 `walk` 方向/步幅试片。
4. **38 帧**齐全，逐帧检查：数量、顺序、基线、alpha、无缺肢/多肢、无黑边；`walk` 镜像方向与滑步。
5. owner 做一次整体观感确认；通过后才进入代码集成。
