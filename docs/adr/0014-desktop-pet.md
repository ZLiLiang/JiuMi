# ADR-0014 桌宠：置顶透明窗口与逐帧动画

- 状态：已接受
- 日期：2026-11-10
- 来源：地图 [#103](https://github.com/ZLiLiang/JiuMi/issues/103)；2026-11-10 设计定稿；后续目标 [#102](https://github.com/ZLiLiang/JiuMi/issues/102)

## 背景

JiuMi 的品牌形象是用户家里的橘猫：splash 与主页 hero 共用 180×180 的实拍 GIF，应用图标是同一只猫的透明猫头母版。这次要把这只猫从「启动动画」扩展为常驻桌面的桌宠。

现有外壳只有主窗口、splash、错误窗口、关闭询问框和一个管理对话框；没有 Topmost、没有点击穿透、没有桌面层窗口，托盘也只承担显示/设置/退出。桌宠是一个新的顶层窗口，生命周期与主窗口不同：主窗口可以隐藏到托盘，桌宠要继续在；应用退出时它才消失。

需要考虑的约束：

- 现有 GIF 是实拍、带背景、无 alpha、23 帧 100ms；直接当桌宠会带背景、放大糊，也无法做睡觉/被拎起等新动作。
- Avalonia 12 的 `GifImage` 只能循环播放，没有暂停/停止；GIF 的透明只有 1-bit，边缘差。
- Win10 与 Win11 的透明/置顶/焦点行为需要同一套实现；不能依赖 Mica 或 Win11 专属 API。
- 仓库对体积敏感（#66），美术资源不能无限膨胀。
- 桌宠是装饰性功能，默认自动出现会打扰正在用工具的人。

## 决策

1. **独立顶层窗口**：新增 `PetWindow`，160×160 DIP，`WindowDecorations=None`、`Topmost=true`、`TransparencyLevelHint=Transparent`、`Background=Transparent`、`ShowInTaskbar=false`、`CanResize=false`、`ShowActivated=false`。位置由 `PetWindowController` 管理；默认主屏工作区右下角 24 DIP。
2. **默认关闭、显式开启**：`petEnabled` 默认 `false`；设置页「桌宠」开关、托盘「显示小猫」勾选项、右键「隐藏小猫」三处读写同一状态，即时生效并保存。主窗口隐藏到托盘时桌宠保留；应用退出时一起关闭。
3. **位置记忆**：`petX` / `petY` 存物理像素坐标；拖动松手时写一次；启动时按坐标恢复，找不到可见工作区就夹回，显示器/DPI 变化时夹取。与主窗口「不记几何」不同：桌宠的位置就是它的使用状态，丢失后用户每次都要重新摆。
4. **逐帧动画，不用 GIF/Live2D**：38 帧、384×384 透明 PNG、约 10fps；Idle 12 / Blink 3 / React 3 / Drag 2 / SleepIn 4 / Sleep 4 / Wake 2 / WalkOut 8；状态机放 `JiuMi.Application`，UI 只负责换帧和叠加矢量爱心/Zzz。GIF 的 alpha 与控制力不够；Live2D/Spine 的运行时、授权与 Avalonia 集成成本超出 v1。
5. **入场走出版**：启用/启动时，主窗口可见就从内容页右下角走到落点；主窗口隐藏到托盘或最小化时从右侧屏幕边缘（落点同高）走进来。按约 450 px/s 的统一速度（内容页约 1.6s、屏幕边缘约 0.8s，实际按路径长度）。只做进入，收起用 150ms 淡出，不做走回内容页。宠物窗口始终置顶，走路时覆盖在页面之上、不被主窗口裁切；裁切 + 交接的版本记录在 #102。
6. **交互范围**：待机/眨眼、拖拽、单击竖耳 + 爱心、5 分钟无操作睡觉、点击唤醒；双击打开主窗口；右键隐藏/打开设置；托盘可勾选。v1 不做声音、自动走动、点击穿透、工具状态联动。
7. **行为边界**：任何单击/拖拽/右键重置 5 分钟计时，悬停不算；睡着单击先 Wake 不冒爱心；睡着拖拽直接 Drag；隐藏/显示回 Idle；只在 Idle 随机眨眼（4–8 秒）。入场中拖拽/单击立即打断并接管；入场走完后才开始睡眠计时；隐藏时中止入场。双击判定用系统 `GetDoubleClickTime()`（通常 500ms），单击爱心延迟 300ms，双击命中时隐藏爱心并打开主窗口。
8. **Win10/11 同一路径**：只用跨版本 API，不依赖 Mica/圆角/阴影；Win10 19045、100% 缩放为实机验收基线；Win11 按手动清单验证。原型已验证 `WS_EX_NOACTIVATE` + `WS_EX_TOOLWINDOW` + `WM_MOUSEACTIVATE` 钩子 + `Focusable=false` 仍无法阻止 Avalonia 激活宠物窗口；v1 接受「点击/拖拽把宠物窗口带到前台」这个已知限制，另开 spike 研究无焦点宿主窗口，不为版本分叉。
9. **未来桌面层双模式只留接缝**：v1 不做 `IPetLayer` 抽象；`PetWindowController` 收拢窗口创建、置顶、位置、入场路径与显隐，ADR 与 #102 记录桌面层、裁切交接与走回内容页是后续扩展。真正实现时再重构。
10. **资源缺失降级**：透明窗口不可用或美术帧缺失/加载失败时，不显示桌宠，保留 `petEnabled` 状态并记 Warning；不弹模态、不画黑框。用户可从设置/托盘关闭开关。

## 为什么是独立窗口，而不是主窗口里的浮层

主窗口可以隐藏到托盘、可以被最小化、会被其他窗口盖住；桌宠要一直浮在桌面上，生命周期比主窗口长。把宠物画在主窗口里，主窗口一关就没了；要让它常驻，还得把主窗口改成永不关闭，破坏现有壳行为。独立窗口的代价是多一个顶层窗口和一套位置/显隐逻辑，但换来的是清晰的边界。

## 为什么置顶，而不是桌面层

桌面层（只在桌面上、被普通窗口盖住）需要 Win32 底层窗口/Progman 关系、Explorer 重启恢复、多屏与全屏处理，v1 的收益不足以抵消复杂度。置顶只多一个 `Topmost`，也符合用户对「桌宠跟着我」的预期；全屏应用被盖住的问题记录在 #102，先接受。

## 为什么默认关闭

桌宠是一个置顶装饰，升级后自动出现会打扰正在用工具的人。默认关闭让用户主动选择，也让 v1 能观察真正愿意开启的人怎么用。以后想改默认值，只需改默认，不影响存储契约。

## 为什么逐帧，而不是 GIF 或 Live2D

- **GIF**：现有实拍 GIF 带背景、无 alpha；重新抠图后仍有毛发边缘和光照问题；`GifImage` 只能循环，不能按状态暂停/切换。
- **Live2D/Spine**：动效更顺，但体积主要看纹理图集，和 30 帧 PNG 同量级；真正贵的是运行时集成、SDK/编辑器授权、绑定与维护。v1 没有理由先背这套工具链。
- **逐帧**：384 PNG 的 alpha 干净、美术可迭代、状态切换完全可控，Avalonia 只需换 `Image.Source`；30 帧的体积和内存都可接受。

## 为什么 38 帧、384、10fps

- 30 帧基础覆盖所有 160px 状态，且能让 Idle 有呼吸 + 尾巴、Blink 只改眼睛、Sleep 有过渡；入场再加 8 帧侧/3-4 走路循环，总计 38。20 帧在 160px 下会明显跳，40+ 帧会把 v1 拖长。
- 384 是 160 DIP 在 200% 缩放下的 1.2 倍，足够清晰；512 会把磁盘/内存抬高一档，而 384 已给未来 200 DIP 留了余量。未来真加尺寸档位再升 512。
- 10fps 是绘本逐帧的节奏，160px 的小图不需要 60fps；窗口位移按 60fps 插值，走路帧按 10fps 循环；隐藏时停表，CPU 成本接近零。原型矢量占位在 Release 下约 1.56% 系统（可见）/0%（隐藏），最终图像帧方案在 feat-3 再实测，目标仍是 <1% 系统。

## 为什么记位置，而主窗口不记

[ADR-0005](./0005-window-state-memory.md) 拒绝主窗口几何，是因为主窗口的尺寸/最大化/位置是一整套机器状态，夹取与 DPI 换算复杂，收益只是省一次拖拽。桌宠只有「一个点 + 固定 160」：用户把它拖到副屏、桌面角落，位置就是它的使用状态；不记的话每次启动都要重新摆。代价只是一对整数和一次松手写盘，夹取逻辑也只服务这一个窗口。

## 备选与取舍

| 备选 | 为什么没选 |
| --- | --- |
| 主窗口内浮层 / 画在内容岛 | 主窗口一隐藏/关闭就没了；要常驻得改壳生命周期 |
| 直接在 v1 做桌面层 | Win32 底层窗口、Progman、Explorer 重启、多屏全屏，复杂度和收益不匹配 |
| 默认开启 | 置顶装饰会打扰升级用户；先让用户主动选择 |
| 复用 splash GIF | 带背景、无真 alpha、180px 低清，且无法做新动作 |
| Live2D/Spine | 运行时/授权/绑定成本高；体积并不比逐帧小一个量级 |
| 不做入场 / 从任务栏起步 | 不做入场浪费最可见的一刻；任务栏/托盘位置随系统变化，v1 用右侧屏幕边缘更稳 |
| 点击穿透 | 与点击反应/拖拽冲突；工作模式记录在 #102 |
| 记整窗尺寸/缩放 | v1 固定 160；尺寸档位在 #102 |
| 资源缺失时画黑框/占位牌 | 装饰功能不应在失败时抢注意力；静默隐藏 + Warning 更符合现有降级习惯 |

## 后果

**正面**

- 桌宠与主窗口生命周期解耦：主窗口收进托盘，猫还在；退出应用才消失。
- 逐帧方案完全可控，美术替换不会牵动运行时；没有新增第三方依赖。
- 默认关闭 + 三处入口，用户可随时收起，不打断工作。

**负面（明确接受的代价）**

- 多一个顶层窗口、一个位置持久化状态和一套动画状态机。
- 160×160 是矩形命中区，透明角落也可能接点击；v1 接受。
- 置顶会盖住全屏应用；v1 接受，自动让位在 #102。
- v1 接受点击/拖拽把宠物窗口带到前台；`WS_EX_NOACTIVATE` 等方案已实测无效，无焦点宿主另开 spike。
- 38 帧 384 PNG 会增加几 MB 安装体积；具体增量在实现票记录。
- 入场走出版多一套路径/起点/窗口位移逻辑与 8 帧走路循环；裁切交接与走回内容页不在 v1。

**中性**

- Win10/Win11 共用一套实现；Win11 的实际观感由手动清单确认。
- 桌宠不接工具状态，也不参与托盘错误通知。
