# ADR-0015 我的JiuMi：页面优先与双模式边界

- 状态：已接受
- 日期：2026-11-11
- 取代：[ADR-0014](./0014-desktop-pet.md)
- 来源：地图 [#103](https://github.com/ZLiLiang/JiuMi/issues/103)；2026-11-11 方向定稿；美术方向 [#117](https://github.com/ZLiLiang/JiuMi/issues/117)；后续桌面模式 [#122](https://github.com/ZLiLiang/JiuMi/issues/122)

## 背景

[ADR-0014](./0014-desktop-pet.md) 把品牌猫做成了独立的置顶桌面宠物：默认关闭，启用后常驻桌面，带入场走动、拖拽、托盘与设置开关，美术方向是轻写实/AI 渲染的 38 帧。

2026-11-11 的 grilling 推翻了这套方向：

- owner 判定旧 38 帧写实/AI 猫「诡异」，随后几何扁平、手绘绘本、半写实三版方向也都被否；最终确认描边插画方向（[#117](https://github.com/ZLiLiang/JiuMi/issues/117)）。
- owner 更想要「打开 JiuMi 就能看到猫」的页面体验，而不是一只飘在所有窗口之上的宠物。猫首先应该属于 JiuMi，而不是桌面装饰。
- 桌面宠物带来置顶、焦点抢占、全屏遮挡、托盘与设置入口、屏幕坐标恢复等一整套外壳复杂度；v1 的收益不足以先承担这些。
- 现有实现分支 [#108](https://github.com/ZLiLiang/JiuMi/issues/108) 保留作桌面模式参考，不合并；#109、#110 作废；#112 parked。

本 ADR 只定方向与边界：页面优先、页面模式与桌面模式的分工、v1 取舍、美术方向。具体页面行为见 [`docs/ui-spec.md`](../ui-spec.md)，分层与状态机见 [`docs/architecture.md`](../architecture.md)，美术交付见 [`docs/pet-art-spec.md`](../pet-art-spec.md)。

## 决策

1. **我的JiuMi 是一个页面，不是窗口**：入口在左侧导航，页面落在现有内容岛里，参与现有导航与切页动效。v1 不创建置顶窗口、不加托盘项、不加全局开关。
2. **v1 先做页面模式**（主窗口内容区内；[#118](https://github.com/ZLiLiang/JiuMi/issues/118) 中称「窗口模式」）：猫生活在内容区的极简房间里，约 200 DIP，默认趴姿待机。支持眨眼、5 分钟睡眠、Wake、起身/伸懒腰、页面内走路；点击猫给反应与爱心，水平拖拽并记忆归一化 X，双击地面空白处召唤，清醒时自主闲逛。离开页面（切页、主窗口隐藏或最小化）暂停并重置，再次进入从趴姿待机开始。
3. **双模式边界**：页面模式的生命周期跟随页面可见性，位置是页面内的归一化水平坐标；桌面模式是后续票（#122）的独立置顶窗口，涉及屏幕坐标、拖出/走回、走出/走回过渡与全局入口。两种模式共用角色、美术与状态语义，但不共用宿主窗口与生命周期。v1 不做 `IPetLayer` 之类的预抽象；桌面模式真正开始时再决定复用范围。
4. **没有全局开关与外围入口**：v1 删除设置页「桌宠」分区、托盘「显示小猫」项与右键菜单。猫只在进入「我的JiuMi」页面时存在；页面本身就是入口。旧键 `Shell.Pet.*` / `Settings.Pet.*` / `Shell.Tray.ShowPet` 退役，桌面模式票若需要再重新登记。
5. **状态机在 Application，房间与输入在 UI**：`MyJiuMiStateMachine`、`MyJiuMiAnimationCatalog` 与状态枚举放在 `JiuMi.Application`，纯逻辑、注入时间与随机源；页面、帧渲染、爱心/`Zzz` 叠加与指针事件留在 `JiuMi` 层。位置只持久化归一化 X，不保存屏幕坐标或窗口几何。
6. **美术改为描边插画**：粗深棕轮廓、自然猫比例、杏仁半垂眼、原创橘猫特征；平涂加少量柔和暗部，无毛发细节、渐变或 AI 质感。方向以 [#117](https://github.com/ZLiLiang/JiuMi/issues/117) 为准，最终帧数与时长在 #117 定稿后由 [#121](https://github.com/ZLiLiang/JiuMi/issues/121) 冻结。旧 38 帧写实/AI 资源与相关导出约定作废。
7. **旧桌面实现只作参考**：[#108](https://github.com/ZLiLiang/JiuMi/issues/108) 分支保留，不合并；[#109](https://github.com/ZLiLiang/JiuMi/issues/109)、#110 已作废；#112 parked。桌面模式由 #122 重新设计，不从旧分支直接续写。

## 为什么是页面优先，而不是继续做桌面宠物

页面优先把猫放回产品内部：

- **可发现**：用户打开 JiuMi 就能在导航里看到「我的JiuMi」，不需要先知道托盘或设置里有个开关。
- **不打扰工作**：猫只存在于自己的页面，不置顶、不盖住全屏应用、不抢焦点，也不需要在托盘里留入口。
- **外壳零改造**：沿用内容岛、导航、切页动效与页面生命周期，不新增顶层窗口、位置恢复、显示器/DPI 夹取与 Win32 互操作。
- **先把角色与交互做对**：页面模式足以验证美术、状态机、点击/拖拽/召唤与睡眠节奏；这些经验对桌面模式同样有效。

代价是猫不再「跟着用户」；这是 v1 明确接受的取舍。桌面陪伴的价值留给 #122，先把页面体验做成用户愿意打开的样子。

## 页面模式与桌面模式的边界

| 维度 | 页面模式（v1） | 桌面模式（#122，后续） |
| --- | --- | --- |
| 宿主 | 内容岛内的页面 | 独立置顶窗口，可能再加桌面层 |
| 可见性 | 只在页面可见时活动 | 可常驻，主窗口隐藏后仍在 |
| 生命周期 | 进入页面激活，离开暂停并重置 | 应用级生命周期，显隐由全局状态控制 |
| 位置 | 页面内归一化 X（`0`–`1`） | 屏幕物理坐标，跨屏/DPI 夹取 |
| 入口 | 左侧导航 | 托盘/设置等全局入口，另行设计 |
| 交互 | 点击、水平拖拽、双击召唤、自主闲逛 | 拖出/走回、走出/走回、置顶相关的取舍 |
| 共用 | 角色、美术、状态语义与动画清单 | 同左，但宿主与调度独立 |

- 两种模式**不是同一套窗口代码的两个配置**：页面模式没有窗口，桌面模式没有页面。共享的是角色与状态语义，不是生命周期。
- v1 不预留 `IPetLayer` 或双宿主抽象；等 #122 明确桌面模式的窗口、拖出与恢复路径后，再决定复用哪些 Application 逻辑。
- 页面模式的睡眠、眨眼、闲逛计时都随页面停表；桌面模式需要自己的调度与恢复规则，不能直接照搬。

## 为什么桌面模式延后

桌面模式不是「把页面猫搬到窗口里」那么简单：

- 置顶窗口、焦点抢占、全屏遮挡、多屏与 DPI、屏幕坐标恢复、托盘与设置入口，都会重新进入外壳范围；旧实现已在这些点上留下已知限制。
- 拖出/走回与走出/走回过渡需要窗口位移、裁切交接与路径设计，是独立的设计问题。
- 页面模式已经能验证美术与交互；在角色还没被 owner 接受前投入桌面宿主，容易把返工放大。
- 旧分支 #108 的实现基于旧窗口方向与旧美术，直接续写会把历史包袱带进来；#122 应重新设计。

因此 v1 只做页面模式，把桌面模式记在 #122；#102 继续记录更远的扩展目标。

## v1 取舍

**做**

- 入口：左侧导航，独立「我的JiuMi」页面。
- 房间：墙、地板线、很淡的接触阴影；猫约 200 DIP，无卡片、无设置控件。
- 状态：趴姿待机、眨眼、睡眠进出、Wake、起身/伸懒腰、走路。
- 轻交互：点击反应 + 爱心、水平拖拽并记忆归一化 X、双击地面召唤、自主闲逛、5 分钟睡眠。
- 生命周期：离开页面暂停/重置；再次进入从趴姿待机开始。

**不做**

- 全局显示开关、托盘项、设置页桌宠分区、右键菜单。
- 桌面模式、拖出/走回、走出/走回、置顶/点击穿透/桌面层。
- 声音、跟随鼠标、工具状态联动、皮肤/命名/尺寸档位。
- 竖直播拖、屏幕坐标记忆、跨显示器行为。

**接受的代价**

- 猫只在「我的JiuMi」页面可见，不能常驻桌面。
- 页面离开即重置，用户回来时看不到离开前的睡眠或走路状态。
- 位置只记水平归一化 X，不记垂直或屏幕位置。
- 左侧导航多一个条目；这是产品入口，不是装饰。

## 美术方向

- 描边插画：粗深棕轮廓（约 5–6px @ 200 DIP）、圆角连接，轮廓承担主体结构；猫的比例自然（约 3–3.5 头身），不 chibi、不做 logo 化。
- 眼睛：杏仁眼、可见上眼睑、琥珀虹膜、竖瞳、白色高光；默认半垂眼、微不爽。不要圆点眼或正面瞪视。
- 毛色：橘色虎斑 + 深橘条纹、白口鼻/胸口/爪子、粉鼻；条纹与白色块不单独描边，只被身体外轮廓包住。
- 绘制：平涂 + 少量柔和暗部；不要毛发细节、渐变或 AI 质感；姿态像插画（趴、伸懒腰、舔爪、走路），不要正面站着盯人。
- 帧数、逐帧时长与导出规格在 #117 定稿后由 #121 冻结；本 ADR 不继承旧 38 帧/10fps/384px 的数字。

## 备选与取舍

| 备选 | 为什么没选 |
| --- | --- |
| 继续做 ADR-0014 的桌面宠物 v1 | 美术方向被否；置顶/焦点/全屏/托盘/位置恢复的复杂度与 v1 收益不匹配 |
| 页面 + 桌面同时做 | 两套宿主与生命周期一起上，角色未定稿前返工面太大 |
| 保留全局开关，页面作为桌面的另一种形态 | 用户仍需先发现开关；页面本身就能承担入口，v1 不需要第二套显隐状态 |
| 在主窗口内做浮层但跨页常驻 | 跨页浮动会盖住工具内容，和置顶宠物同样打扰工作 |
| 直接复用 #108 分支改成页面 | 旧实现绑定置顶窗口、屏幕坐标与旧美术；改造量不小于重写，且会带入已知限制 |
| 先做 `IPetLayer` 双模式抽象 | 桌面模式尚未设计，抽象会按猜测定形；等 #122 再重构 |

## 后果

**正面**

- 猫成为产品页面的一部分：入口明确、可发现，不打扰其他工具。
- 外壳不改：没有新顶层窗口、没有位置恢复与 Win32 互操作，风险集中在一个页面内。
- 状态机、位置与动画清单可以脱离 UI 单测；美术替换不牵动页面骨架。
- 桌面模式可以基于页面模式验证过的角色与交互重新设计，不被旧实现绑住。

**负面（明确接受的代价）**

- 猫不能常驻桌面；用户必须打开「我的JiuMi」页面才能看到。
- 页面离开即重置，不能把睡眠/走路状态带到下次进入。
- 左侧导航多一个入口；主页工具卡保持四张不变。
- 旧桌面键与入口退役；桌面模式若恢复全局入口需要重新登记键与交互。

**中性**

- 页面模式没有透明窗口、置顶与多屏问题；Win10/Win11 的差异主要落在渲染与主题，不再需要焦点/置顶清单。
- 角色与状态语义为桌面模式保留，但 v1 不承诺窗口层复用。
