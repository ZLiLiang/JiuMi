# ADR-0006 外壳岛屿化：导航与内容各成一块浮岛

- 状态：已接受
- 日期：2026-10-27
- 来源：#52；定稿原型 [`docs/prototypes/island-shell.html`](../prototypes/island-shell.html)（变体 B）

## 背景

外壳此前是「贴边平铺」：40 高通栏透明标题栏 + 左导航列（展开 280 / 收起 48，背景透明）+ 右内容区（InfoBar + 滚动页面）。导航与内容之间没有「面」的边界，层次只能靠 1px 分隔线与留白表达；Mica 只在标题栏那一条透出来，窗口材质基本没被用上。

目标改成「菜单一块岛、内容一块岛」：两块圆角面板浮在 Mica 上，岛与岛之间、岛与窗口边缘之间留出可见的窗口底色。

## 决策

1. **两块岛**：外壳主体是导航岛 + 内容岛两个等高 `Border`；窗口外距 14、岛间缝 14、圆角 12。
2. **岛表面**：新增主题资源 `JiuMiIslandBackgroundBrush`（浅色 `#9EFFFFFF`、深色 `#8C2E3038`）+ 1px `ControlStrokeColorDefaultBrush` + `BoxShadow`（浅色 `0 2 8 #14000000`、深色 `0 4 16 #40000000`）。
3. **标题栏不动**：仍是 40 高通栏透明，角标与应用名在左、系统按钮在右；岛从它下方开始。
4. **导航**：展开 280、收起 56；项高 36、项间距 2、内边距 8 8 8 12、选中态与可访问性全部照旧，只有容器外形变成岛。
5. **内容岛**：InfoBar 是岛内第一行（外边距 12,12,12,0），页面在岛内滚动，页面内边距仍 32 44 36。
6. **卡片不变**：hero、工具卡、设置分组卡继续用 `CardBackgroundFillColorDefaultBrush` + 1px `CardStrokeColorDefaultBrush`，不新增色值、不加投影。
7. **错误窗口**：保留系统边框与标题栏，内容整体内缩 8px 包进一块同款岛。
8. **splash 不动**。

## 为什么是岛

窗口已经有材质（Mica / 回退实色），却把它整块盖住了。岛屿化把材质变成可见的「底」，导航与内容成为浮在上面的两块面：分组关系不靠分隔线，靠「同一块面」表达，读一眼就知道哪部分是导航、哪部分是内容。

这也顺带解决了一个老问题：贴边平铺时，导航栏与内容区在视觉上是同一片底色里的两列，收起导航后画面会「一边空、一边满」；成岛之后，收起只是换一块更窄的岛，画面重心不散。

## 为什么「亚克力」是模拟的

当前技术栈（Avalonia 12.1.4 + FluentAvaloniaUI 3.1.0）没有 in-app 背景模糊：

| 能力 | 结论 |
| --- | --- |
| `AcrylicFillColorDefaultBrush` | 不存在 |
| `AcrylicInAppFillColorDefaultBrush` | 存在，但在 FA 里是 WinUI 的 fallback 实色 `#F9F9F9` / `#2C2C2C`，不透明 |
| `TransparencyLevelHint="AcrylicBlur"` | 只模糊窗口背后的桌面，且会把整窗一起变模糊 |
| 元素级 backdrop blur | 没有；`BlurEffect` 模糊的是元素自身绘制结果 |

所以「亚克力岛」= 半透明画刷叠在 Mica 上，磨砂感由 Mica 本身提供。这在结构上够用：岛的下方永远只有窗口底色，没有内容从岛底下穿过，缺的只是那层额外的模糊。

## 为什么自定义画刷，而不是 `LayerFillColorDefaultBrush`

Fluent 给「Mica 上的内容层」准备了 `LayerFillColorDefaultBrush`：浅色 `#80FFFFFF`（50% 白）、深色 `#4C3A3A3A`（30% 灰）。浅色够用，深色不够——30% 灰叠在深色 Mica 上，岛与缝隙的对比薄到会糊成一片，而「岛能看出来」正是这次改动的全部目的。

自定义档位取浅色 62% 白、深色 55% 深灰，复现定稿原型的观感（原型里那层 `backdrop-filter` 在实现中不存在，只能靠提高不透明度补偿）。代价是它成为规格里的第三处固定配色：浅色、深色、高对比度三档都要单独维护，高对比度下改用实色底 + 描边。

## 为什么是 14 / 14 / 12

- **缝 14**：8 以下两块岛像贴在一起的板子，20 以上窗口显空；14 在 1200 宽下缝隙明确，900 宽（最小尺寸）时内容区仍有 850 左右。
- **圆角 12**：8 在大面积半透明表面上偏硬，16 又会和窗口自身的圆角（系统给的 8）打架；12 与岛的大尺寸相称，也是 hero 卡已有的档位。
- **外距 14 与缝 14 同值**：同值让「窗口边缘 → 岛」与「岛 → 岛」是同一道呼吸，不需要再多一个 token。

## 为什么收起态从 48 改成 56

48 宽配圆角 12 的浮条太瘦，图标几乎贴边，看着像一条残渣而不是一块岛。56 只多 8px，观感立刻稳；代价是收起态内容区少 8px，可接受。展开态 280 不变——那是内容区宽度的主要来源。

## 为什么错误窗口只做「内容岛」

整窗无边框圆角浮窗要重做拖动、焦点循环、Esc / 回车、任务栏行为与屏幕居中，还会牵动错误窗口那批测试（见 [ADR-0003](./0003-error-presentation.md) 的载体约定）。「系统边框 + 内部一块岛」已经和主窗口同一套语言，改动只落在 XAML 的容器上。

## 备选与取舍

| 备选 | 为什么没选 |
| --- | --- |
| 单岛（导航与内容同一块岛，中间 1px 竖线） | 等于回到「没有面」的老问题，只换了圆角；两块并列的岛才表达出导航与内容是两件事 |
| 顶部横向菜单岛 | 菜单项是「主页 + 四个工具 + 设置」，900 宽下横排会挤；竖栏一直是本应用的导航形态 |
| 纯 Fluent 画刷 `LayerFillColorDefaultBrush` | 深色 30% 灰与缝隙对比不足，岛会糊掉 |
| 岛用不透明 `CardBackgroundFillColorDefaultBrush` | 等同于实色块，Mica 只在缝隙出现，材质白搭 |
| 整窗 `AcrylicBlur` | 模糊的是桌面不是窗口内容，且现有 `UpdateBackdrop()` 会把不透明底色填回去 |
| 岛加更重的投影 | 与「靠描边分层」的既有规则冲突；投影只保留岛这一级的极浅档 |
| 圆角 8 / 16 | 8 偏硬、16 与窗口自身圆角冲突 |
| 缝 8 / 20 | 8 像贴板，20 显空 |
| 收起 48 / 收起后隐藏岛 | 48 偏瘦；隐藏岛要另配悬浮按钮并给页面让出顶部空间，行为变化大 |
| 错误窗口做无边框圆角浮窗 | 需重做拖动、焦点、任务栏、居中与对应测试 |

## 后果

**正面**

- Mica 真正成为窗口基底，标题栏与缝隙连成一片「底」。
- 导航与内容有明确的面边界，收起导航不再让画面失衡。
- 两套主题共用同一套结构，只换颜色资源。

**负面（明确接受的代价）**

- 岛表面成为第三处固定配色例外，浅色 / 深色 / 高对比度三档都要维护。
- 引入投影这一视觉层：此前规格只有 `0 1 2` 级别的极浅投影，现在岛这一级是 `0 2 8` / `0 4 16`。
- `BoxShadow` 只有 `Border` 支持，内容岛要多包一层容器。

**中性**

- 页面内边距、卡片、字号、间距全部不变；这次改动只动外壳骨架与两个窗口的容器。
