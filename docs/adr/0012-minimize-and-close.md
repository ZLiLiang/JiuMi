# ADR-0012 最小化与关闭：最小化留在任务栏，关闭时询问

- 状态：已接受
- 日期：2026-11-09
- 来源：设计票 [#71](https://github.com/ZLiLiang/JiuMi/issues/71)；推翻 [#7](https://github.com/ZLiLiang/JiuMi/issues/7) 中「最小化即隐藏」「关闭仍然是退出」两条壳行为，保留单实例与托盘

## 背景

#7 定了单实例与托盘：主窗口最小化即隐藏到托盘，关闭仍然退出。托盘唯一的职责是承接最小化，应用本身没有后台任务。

实际使用中，这两条都偏离 Windows 用户的预期：

- 最小化是「收起但还在任务栏」，不是「消失到托盘」。最小化后任务栏与 Alt+Tab 都找不到窗口，用户会以为应用已经退出；恢复只能靠托盘，第一次还要靠一条系统通知解释。
- 关闭是「结束当前窗口」，但对于一个没有保存按钮、经常被反复打开的工具箱，用户有时希望关掉界面、保留托盘入口，下次瞬间唤回。

#7 的取舍是「最小化留住后台，关闭负责退出」。方向没错，但把两种意图绑在了错误的按钮上。

## 决策

1. **最小化保留任务栏**：最小化不再隐藏窗口、不移除任务栏按钮，也不投递首次最小化通知。
2. **关闭时询问**：用户关闭主窗口时弹询问框，三选一：取消 / 退出应用 / 隐藏到托盘。取消保持窗口；退出走现有退出路径；隐藏到托盘隐藏窗口、从任务栏与 Alt+Tab 移除，进程继续运行。
3. **可记住、可反悔**：询问框带「不再询问」复选框；选择后两个动作之一时写入 `settings.json` 顶层 `closeAction`（`ask` / `minimizeToTray` / `exit`，默认 `ask`）。设置页「窗口」分区可随时改回「每次询问」。界面文案用「隐藏到托盘」，存储值沿用 `minimizeToTray`。
4. **只拦用户主动关闭**：托盘「退出」、系统关机 / 注销（`WindowCloseReason.OSShutdown`）、应用 Shutdown（`ApplicationShutdown`）直接退出，不弹框，避免拖住关机。
5. **托盘不可用时关闭即退出**：没有托盘，「隐藏到托盘」没有恢复入口；此时不弹框，已存 `minimizeToTray` 也回退为退出。
6. **已最小化时先还原再询问**：从任务栏菜单或 Alt+F4 关闭最小化的窗口时，先还原到最小化前的状态，询问框有可见的 owner；取消后保持还原。
7. **托盘保留**：托盘继续承接关闭后的隐藏与唤回，菜单仍是显示主窗口 / 设置 / 退出。

## 为什么

- **最小化的语义要跟系统一致**。任务栏是 Windows 用户找窗口的第一入口；把最小化做成隐藏，等于每台机器都要重新学习一次。托盘仍然存在，喜欢托盘的用户不会失去入口。
- **把「退出」与「留后台」拆成两个明确动作**。同一个关闭按钮既可能表示「我不看了」也可能表示「结束进程」，一次询问把选择权交给用户；记住选择后，日常使用不再被打断。
- **可反悔比一次询问更重要**。只记一个布尔「不再询问」，用户误勾后只能手改 JSON；三值 `closeAction` 加上设置页入口，代价只有一个字符串键。
- **不拦系统关机**。关机 / 注销是操作系统发起的关闭，弹框会阻塞会话结束，属于系统级错误；这些路径直接退出。
- **不做运行中任务检测**。询问框正文统一一句，不把各工具的批次状态接进外壳。任务感知的警告可以另开票，不应成为这次窗口行为改造的前置条件。

## 备选与取舍

| 备选 | 为什么没选 |
| --- | --- |
| 保持 #7：最小化隐藏到托盘、关闭退出 | 最小化偏离系统预期；关闭无法留在后台 |
| 关闭直接隐藏到托盘 | 用户想真正退出时多一步；还会留下一个容易被忘记的常驻进程 |
| 维持关闭退出，只改最小化 | 无法满足「关掉界面、保留托盘」的意图，托盘的唤回职责只剩最小化这个已不需要的入口 |
| 每次关闭都询问，不能记住 | 高频操作被反复打断 |
| 只记布尔「不再询问」 | 误勾后没有界面入口改回，只能手改配置文件 |
| 用系统 MessageBox | 放弃岛式样式、按钮配色与「不再询问」的排版控制 |
| 检测运行中任务并动态警告 | 需要把各工具的状态接进外壳；本期正文静态一句即可 |
| 托盘不可用时仍弹框 | 「隐藏到托盘」没有回路，询问框会给出做不到的选项 |

## 后果

**正面**

- 最小化与 Windows 惯例一致；关闭时用户的两种意图都有明确出口。
- 托盘从「最小化的唯一回路」变成「关闭后留在后台的入口」，职责与用户预期一致。
- 首次最小化通知失去存在理由，一并删除，少一条系统通知文案与一个触发点。

**负面（明确接受的代价）**

- 关闭多了一次询问；勾选「不再询问」后回到一键关闭。
- 关闭询问是模态的，会比直接退出多一层交互；已最小化时还会先把窗口还原。
- `closeAction` 进入半稳定配置契约，虽然只是新增键，但需要维护读取与设置页。

**中性**

- 托盘的图标、菜单与隐藏期错误通知不变。
- 单实例激活规则不变：第二次启动仍然把已有窗口叫到前台。

## 不在本 ADR 内

- 窗口几何记忆：见 [ADR-0005](./0005-window-state-memory.md)。
- 托盘图标、菜单文案与隐藏期错误通知的细节。
- 「有任务正在执行」的动态警告。
- 跨平台托盘；非 Windows 仍为 no-op，其关闭行为随跨平台分发另行决定。
