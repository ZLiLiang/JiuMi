# ADR-0008 世界时钟目录：内置快照、双粒度与代表时区

- 状态：已接受
- 日期：2026-10-28
- 来源：#53；定稿原型 [`docs/prototypes/world-clock.html`](../prototypes/world-clock.html) 与七张参考图 [`docs/images/world-clock-*.png`](../images/)

## 背景

世界工作时间最初只按城市建模：每行一个 IANA 时区，城市名跟随界面语言，没有国家层级，也没有电话区号。实际排会有两种提问方式：「哪些国家在上班」和「哪个城市在上班」；用户还希望在一行里同时读到中英文名，并看到对应的国家电话码。

国家不是单一时刻：美国跨 6 个时区、俄罗斯跨 11 个。把国家做成一行之前，必须先说明这一行代表哪个时区，否则「美国 09:00」会误导。

目录数据还有两个看似矛盾的要求：运行时不能依赖网络（工具必须离线可用），但正式使用时要能更新。结论是把「内置快照」与「在线更新」拆成两张票：本 ADR 定内置快照、数据契约与 provider 接缝；在线更新另票实现（#56 已交付，见决策 11）。

## 决策

1. **地点是统一条目**：`Place` 分 `country` 与 `city` 两种 `kind`；两者都可被选中，已选列表允许混排，行内用「国家/城市」徽标区分。看板、规划、摘要与结论统一用「地点」计数。
2. **国家绑定代表时区**：国家条目绑定一个 IANA 代表时区；多时区国家在行内标注代表城市（如「美国 · 纽约」「澳大利亚 · 悉尼」），单时区国家只显示国名。代表城市取主要商务枢纽，不强制首都；由数据表人工核定。
3. **城市是一城一区**：城市条目绑定一个 IANA 时区，城市 `id` 即 IANA id；同一时区只收一个代表城市，内置城市表策展约 100–150 个主要商务城市。同一时区的其他城市不单列，因为时间、窗口与假日完全相同。国家表覆盖全量 ISO 3166，包含 HK、MO、TW 等有独立区号的地区条目，名称取 CLDR 对应语言短名；无 IANA 时区的无人区（如 BV、HM）跳过。
4. **区号只取国家码**：国家与城市行都显示所属国家的电话区号（ITU / libphonenumber），如 `+86`、`+1`；不显示城市固话区号。NANP 只显示 `+1`，不展开 `+1 809` 之类的子码。
5. **中英文始终同显**：主行跟随界面语言（中文界面中文在前，英文界面英文在前），次行是另一种语言。看板两行、规划三行（第三行当地时间与星期），规划标签列 176px、行高 50px；超长英文省略号。
6. **内置快照**：`Assets/world-clock/{countries,cities,office-hours}.json`。国家条目形如 `{ iso2, name, dialCode, representative: { zone, city? } }`，`city` 只在多时区国家出现；城市条目形如 `{ id(IANA), country, name }`。`tools/generate-world-clock-data.ps1` 在开发期从 CLDR（中英短名）、IANA tzdb（代表时区）、libphonenumber（区号）生成；JSON 内记录源版本与链接。脚本不进构建、不接 CI，生成物随应用发布，作为离线回退。
7. **设置契约**：`worldClock.places: [{ kind, id, start, end, days }]`。国家 `id` 为 ISO alpha-2，城市 `id` 为 IANA；时间粒度 15 分钟，`days` 为 ISO 1–7。默认仍为上海、伦敦、纽约、旧金山四个城市；旧 `cities` 键不保留（功能未发布）。
8. **工时默认**：全球默认 09:00–18:00、周一至周五；只对已知例外做国家级覆盖（如中东周日至周四），城市级覆盖只给策展城市；`office-hours.json` 记录来源链接与更新日期。回退链：城市 → 国家 → 全球。
9. **目录接缝**：`IWorldClockCatalogProvider` 是页面唯一的数据入口。内置实现保证离线可用；在线实现先读校验通过的缓存、再回退内置，换实现不改页面。
10. **文案统一为「地点」**：「管理地点」、摘要、结论、页脚都用地点；`Tool.WorldClock.Description` 改为「查看不同国家或城市的工作时间重叠。」英文本地化用 location(s)。
11. **在线更新（#56）**：目录以 GitHub Release 资产发布，固定 tag `world-clock-catalog` 同时承载 `manifest.json` 与三份 JSON，资产名与 URL 稳定。manifest 形如 `{ schemaVersion, version, updatedAt, files: [{ name, sha256, size }] }`，`version` 单调递增（默认取发布日 `yyyyMMdd`，发布脚本拒绝不高于已发布版本的 manifest）。每个数据版本由哈希固定：发布顺序为先三份 JSON、后 manifest，发布窗口内的哈希不匹配会被校验拒绝，下一轮检查自动恢复。应用启动后后台检查，24 小时至多一次；设置页「立即检查」可强制。下载后校验 schema、SHA-256 与大小，全部通过才原子写入 `<设置同根>\cache\catalog\{version}\`，只保留最新一份；写失败不影响会话。任何失败都静默处理（Warning 日志，不弹 InfoBar），回退顺序为缓存 → 内置快照。设置页「数据与联网」关闭后不发起任何请求，缓存仍可读。

## 为什么

- **国家作为条目是用户的语言**：用户会说「日本团队」「美国同事」，不会先想到东京或纽约。代表时区 + 代表城市让这一行可解释，避免「一个国家一个时间」的错误暗示。
- **只给多时区国家标代表城市**：单时区国家没有歧义；为约 250 个国家补城市双语名是纯负担，也会让行内信息过密。
- **国家码稳定、有用**：跨境排会最需要的是「加拨哪个国家码」；城市固话区号随城市/运营商变化，一城多码，不适合做内置数据。
- **始终双显直接满足需求**：主次随界面语言，中文用户与英文用户都能先读到自己熟悉的名称；两行标签同时解决了 176px 规划标签列放不下「旧金山 San Francisco」的问题。
- **全量国家 + 策展城市**：避免「搜不到某国」；城市控制在常排会的商务城市，避免长尾与翻译成本。
- **内置快照让首版可独立验收**：离线可用、可单测、可发布；生成脚本让 250 国数据可复现、可审查；在线更新拆票避免把 provider、缓存、manifest 校验塞进首版。
- **混排列表支持真实场景**：「纽约同事 + 日本团队」可以同时出现在一张网格里；页面级两套列表会强迫用户为整张网格选粒度。
- **在线更新走 Release 资产 + manifest**：数据不随应用发版即可修正；manifest 里的哈希让「下载到半份文件」和「发布到一半」都可识别，原子目录写入保证页面永远读到一个完整版本。24h 节流把启动时的网络开销控制在每天一次，失败静默则不把增强信息变成主路径的打扰。

## 备选与取舍

| 备选 | 为什么没选 |
| --- | --- |
| 国家只作浏览分组，选中后展开一组城市 | 一次塞入多行，用户无法只加「一个国家」；行数不可控 |
| 国家按该国全部 IANA 时区各出一行 | 美国 6 行、俄罗斯 11 行，多数时区不是业务城市 |
| 代表城市固定取首都 | 美国华盛顿、澳大利亚堪培拉不是主要商务枢纽；观感与用途都弱 |
| 城市行显示固话区号 | 数据不稳定、一城多码；与跨境排会的用途不匹配 |
| 页面级「国家/城市」两套列表 | 不能混排，状态翻倍，切换后上下文丢失 |
| 名称只跟随界面语言 | 不满足「同时呈现中英文」的要求 |
| 全量国家 + 全量城市 | 城市翻译与审核成本失控，长尾城市无人使用 |
| 运行期从第三方 API 取目录 | restcountries 的 timezones 只有偏移量、没有 IANA id，无法支撑代表时区 |
| 运行期从仓库 raw 分支取目录 | 分支内容可变，缓存/回滚不可控；在线更新改用 Release 资产 + manifest 哈希校验 |
| 在线更新按版本并存多份缓存 | 目录只在「下次进入页面」生效，旧版本没有回滚用途；只留最新一份，校验失败就回内置 |
| 手动检查也受 24h 节流 | 用户点「立即检查」就是要现在知道结果；节流只约束自动检查 |
| 手写国家表 | 250 个国家的名称、区号与时区容易错漏；生成脚本可复现、可审查 |

## 后果

正面：

- 国家与城市两种提问方式都能直接落到网格；中英文与区号同屏。
- 目录离线可用，首版可独立验收；数据生成可复现。
- 搜索可按国家、城市、代表城市、区号命中；混合列表可拖动排序。

负面（明确接受的代价）：

- 多时区国家需要人工核定代表城市与双语名（约 30 个）；全量国家的名称与区号需要一次审校。
- 同一时区只保留一个代表城市，同区的其他城市（如北京 / 上海）不能同时出现在城市目录；需要该城市名时只能选代表城市或国家条目。
- 规划标签列 176px、行高 50px，24 列网格比原设计窄，900×600 下更早触发横向滚动。
- 国家条目只能改工作窗口/工作周，不能改代表时区；要精确时区必须选城市。
- 在线更新与内置快照共用同一份数据契约：新版本目录在下次打开页面时生效，发布后需要一天左右才会被大多数安装取到。
- 目录缓存与设置同根，用户清理配置会一并清掉已下载的目录版本。

中性：

- 节假日仍按国家码请求；国家条目用代表时区的本地日期判定，城市条目用城市时区（见 [ADR-0007](./0007-holiday-network.md)）。
- 不新增状态配色；双语名与区号都复用现有文本层级与 chip。

## 不在本 ADR 内

- 在线更新器的实现细节（HTTP 重试、缓存目录布局、状态文案）：见 [`docs/architecture.md`](../architecture.md) 的工具模块章节。
- 节假日 provider、缓存与开关：[ADR-0007](./0007-holiday-network.md)。
- ui-spec 的像素级列表与 architecture 的模块分层：随 #53 实现更新。
- 国家代表时区在行内修改、城市固话区号、为所有国家补代表城市双语名：明确不做。
- 后台常驻轮询、增量更新、签名发布：明确不做；检查每天至多一次，失败静默。
