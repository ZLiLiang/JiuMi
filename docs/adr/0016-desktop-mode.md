# ADR-0016 桌面模式：双宿主、拖出/拖回与走出/走回

- 状态：已接受
- 日期：2026-11-11
- 来源：设计票 [#122](https://github.com/ZLiLiang/JiuMi/issues/122)；地图 [#103](https://github.com/ZLiLiang/JiuMi/issues/103)；页面优先决议 [ADR-0015](./0015-my-jiumi-page.md)
- 前置：ADR-0014 的置顶透明窗口行为与 [#108](https://github.com/ZLiLiang/JiuMi/issues/108) 分支；[#112](https://github.com/ZLiLiang/JiuMi/issues/112) 的无焦点结论

## 背景

ADR-0015 把 v1 定为页面优先：猫只生活在「我的JiuMi」页面，离开页面即暂停并重置；桌面模式、拖出/走回与走出/走回留给 #122。本文补上这套后续形态的设计，只定契约，不写实现。

#122 的已定输入：

- 桌面模式沿用现有置顶透明 160×160 窗口行为，只换描边插画、简化交互；v1 不交付。
- 双向过渡：窗口 → 桌面可拖出/走出；桌面 → 窗口可拖回/走回；页面是「家」。
- 允许对裁切、交接、焦点、多屏、DPI 做取舍；页面模式先上，本票只做设计。

2026-11-11 与 owner 确认的取舍：

- **走出**：主窗口最小化或隐藏到托盘、且猫清醒时，猫自动走到桌面并留下；页面内不加按钮。
- **走回**：把桌面猫拖回页面，或在页面双击地面召唤；双击桌面猫只打开页面，不自动召回。
- **重启**：永远回页面；桌面模式与屏幕坐标只在本次会话有效。
- **桌面交互**：单击反应 + 拖动移动 + 双击打开页面；无右键菜单、无自主闲逛。

现有实现与历史约束：

- 页面猫在内容岛里，房间 `ClipToBounds`，约 200 DIP；状态机 `MyJiuMiStateMachine` 在 `JiuMi.Application`，页面视图模型持有计时器、帧缓存与归一化 X 保存。
- 桌面置顶窗口已在 [#119](https://github.com/ZLiLiang/JiuMi/issues/119) 移除；[#108](https://github.com/ZLiLiang/JiuMi/issues/108) 分支的 `PetWindowController` / `PetPlacement` 只作参考，不能直接续写。
- [#112](https://github.com/ZLiLiang/JiuMi/issues/112) 已实测：`WS_EX_NOACTIVATE`、`WM_MOUSEACTIVATE`、`Focusable=false` 的组合仍会让点击把宠物窗带到前台。桌面模式接受这个已知限制。
- 仓库对体积与常驻成本敏感：页面离开即停表，桌面模式也不能留下不可见的后台窗口或计时器。

## 决策

### 1. 模式、家与会话

猫只有两种归属，由 `MyJiuMiPresence` 表示：`Home`（页面）、`Leaving`（去桌面）、`Desktop`（桌面）、`Returning`（回页面）。

- **页面是家**：默认、启动与恢复后的归属都是 `Home`；猫在页面里的归一化 X 仍是唯一持久化的位置。
- **同一时刻只有一个宿主显示猫**：页面模式由 `MyJiuMiView` 渲染，桌面模式由 `MyJiuMiDesktopWindow` 渲染；切换时先交接、再隐藏旧宿主，不出现双影。
- **会话只活一次运行**：桌面模式、屏幕坐标、桌面睡眠状态都不写设置；重启后猫在 `Home`，位置取 `myJiuMi.x`。这样不新增设置键，也不把置顶宠物变成升级后的默认惊喜。
- **共享一个会话**：把状态机实例、帧缓存与 16 ms `DispatcherTimer` 从页面视图模型上移到一个 UI 层会话对象（`MyJiuMiSession`）；页面与桌面窗都只是会话的渲染/输入适配器。每个宿主不各跑一套状态机，避免睡眠计时、帧序与位置分叉。

状态迁移：

```text
Home --拖出 / 走出--> Leaving --宿主就绪--> Desktop
Desktop --拖回 / 双击召唤--> Returning --页面就绪--> Home
Leaving --失败 / 取消--> Home
Returning --失败 / 页面不可见--> Desktop
```

`Leaving` / `Returning` 是短过渡态，只允许一次在途迁移；重复的隐藏/最小化/拖拽事件在过渡态里被忽略。

### 2. 拖出：页面 → 桌面

- 拖拽位置（指针）越过房间边缘 **48 DIP** 后松手：指针在房间外 → 以猫底边中心在松手位置创建桌面窗；指针在房间内 → 回弹到房间内，不进入桌面。
- 拖拽期间猫提升到窗口级覆盖层，可以越过房间边框和页头；主窗口内的部分仍受其裁切，越过主窗口边缘后由桌面预览窗接续显示；房间自身的 `ClipToBounds` 不参与这只临时猫层。这样用户能看到猫被拖出房间，而不是在房间边缘凭空消失。
- 2026-11-13 验收补充：页面窗口继续持有指针捕获；猫的 200 DIP 槽位越过主窗口边缘时，提前显示临时桌面预览窗（200 DIP，跟随猫底边中心），松手仍按原规则提交或回弹，回弹时关闭预览窗。
- 交接以松手为准，**不做跨窗口连续拖拽**：Avalonia 的指针捕获不能跨 HWND，鼠标一直按住时把猫交给另一个窗口需要 Win32 捕获与按钮状态接管。连续拖出另开 spike；本设计用「松手提交」换确定性和可测性。
- 提交失败（桌面窗创建失败、透明不可用、帧缺失）时猫回弹到房间，记 Warning；不弹窗。

### 3. 走出：最小化/隐藏到托盘

触发条件同时满足才走出：

1. 主窗口正在最小化，或用户选择隐藏到托盘；
2. 「我的JiuMi」是当前页面；
3. 猫清醒（不是 `SleepIn` / `Sleep`）；
4. 桌面宿主可用。

行为：

- **隐藏到托盘**：猫从当前位置走向最近的一侧房间边缘，边走边缩小；主窗口最多等 **900 ms** 再隐藏。猫先到边缘就从边缘交接，没到就在当前屏幕位置交接，桌面窗接住后继续走一小段再落定。延迟只发生一次，退出、关机、关闭询问取消等路径不等待。
- **最小化**：窗口已经最小化，走路不可见；猫在最小化前的最后屏幕位置出现，桌面窗用 150 ms 缩放/淡入接住，再走一小段落定。这是与隐藏路径的明确差异，不尝试拦截系统最小化来补播动画。
- **不走出**：猫在睡、页面不是当前页、桌面宿主不可用，或用户正在关闭/退出应用。此时沿用现状：页面暂停并重置，隐藏/最小化立即执行。
- 走出期间忽略指针交互；用户仍可以用托盘显示/退出，退出直接取消迁移并关窗。

### 4. 拖回：桌面 → 页面

- 把桌面猫拖到「我的JiuMi」房间的可见范围内松手：关闭桌面窗，页面猫在投影出的归一化 X 出现，做 120 ms 的放大与落定；写入 `myJiuMi.x`。
- 页面不可见、当前页不是「我的JiuMi」、或松手点不在房间可见矩形内：不交回；桌面窗夹回最近工作区，猫留在桌面。
- 拖回不要求用户精确放在地板上：用猫底边中心与房间地板线做投影，垂直方向按落点夹到地板；水平方向按房间可见宽度归一化并夹回 `0`–`1`。
- 主窗口在另一块显示器时，按房间实际屏幕矩形投影；窗口被内容岛滚动裁掉的部分不算可见房间。

### 5. 走回：双击召唤

- 猫在桌面时，页面房间是空的，并在房间底部显示一行弱化提示 `MyJiuMi.DesktopHint`（「小猫在桌面上，双击地面叫它回来」）。
- 双击地面空白处：桌面窗关闭，猫从房间左/右边缘走进来，走到双击位置；从哪一侧进由桌面猫最后的屏幕 X 与房间屏幕中心的相对位置决定。走动复用 `Walk` 帧，目标 X 写回 `myJiuMi.x`。
- 猫睡着时召唤：先 `Wake` 再走进来，与页面内召唤一致；不冒爱心。
- 双击桌面猫：恢复并激活主窗口，导航到「我的JiuMi」；猫**留在桌面**，不自动召回。页面此时显示空房间与提示，用户可再双击地面召回。
- 走回失败（页面已不可见、桌面窗关闭失败）：桌面窗保持原状，记 Warning；下一次召唤重试。

### 6. 宿主与渲染

采用**双宿主**：

| 宿主 | 渲染 | 生命周期 |
| --- | --- | --- |
| 页面 `MyJiuMiView` | 房间、地板、接触阴影、猫、爱心/`Zzz` | 随主窗口；页面不可见时停表 |
| 桌面 `MyJiuMiDesktopWindow` | 透明窗里的猫、爱心/`Zzz`；无房间、无阴影 | 进入桌面或拖拽预览时按需创建，回家/回弹即关闭 |

桌面窗口属性沿用 ADR-0014：160×160 DIP、`WindowDecorations=None`、`Topmost=true`、`TransparencyLevelHint=Transparent`、`Background=Transparent`、`ShowInTaskbar=false`、`CanResize=false`、`ShowActivated=false`、手动定位。拖拽预览期使用同一宿主、尺寸为 200 DIP，交接后回到 160 DIP。

- 桌面窗懒创建、回家即 `Close()`；不保留隐藏窗口或后台计时器。会话计时器只在 `Home` 页面可见或 `Desktop` 时运行。
- 帧缓存由会话共享，页面与桌面窗不各解码一份；桌面窗按 160 DIP 绘制（拖拽预览期为 200 DIP），源帧仍是 400×400。
- 爱心与 `Zzz` 继续是矢量叠加，按 160/200 的比例缩放；不烘焙进帧。
- 桌面窗不画接触阴影：透明窗口没有可信的地面，阴影会在任意桌面背景上变成脏斑。页面阴影在交接时淡出。
- 透明窗口的 160×160 是矩形命中区，透明角落也会接点击；v1 接受，与 ADR-0014 一致。

### 7. 位置、比例与锚点

- 页面 200 DIP，桌面 160 DIP（沿用 #122 已定输入）。交接用猫的**底边中心**做锚点，做 120 ms 的 200 ↔ 160 缩放插值；走路帧与拖拽帧共用，不新增交接专用美术。
- 页面 → 桌面：锚点在主窗口里的屏幕坐标，就是桌面窗底边中心的落点；桌面窗左上角 = 锚点 − (80, 160) DIP × 目标屏缩放。
- 桌面 → 页面：锚点投影回房间地板；桌面窗关闭与页面猫出现在同一帧，避免双影。
- 多屏：交接按落点所在显示器取缩放；位置夹回该屏工作区。拖拽可跨屏，屏幕坐标只在会话内保存。
- DPI 变化或显示器移除：按最近可见工作区夹回，按新缩放重绘；不写设置，不迁移。桌面窗的 DIP 尺寸不变。

### 8. 交互与调度

- 桌面模式保留：`LyingIdle`、`Blink`、`React`（单击 + 爱心）、`Drag`、`SleepIn`、`Sleep`、`Wake`。**不**做自主闲逛、双击召唤、右键菜单、声音、工具联动、跟随鼠标。
- 睡眠继续 5 分钟：单击/拖拽重置；睡中单击先 `Wake`，睡中拖拽直接 `Drag`；`Zzz` 叠加。桌面窗上的睡眠计时不随主窗口隐藏而暂停，这是桌面模式与页面模式的核心差异。
- 拖动以 4 DIP 阈值区分点击；松手只夹取屏幕位置，不写设置。拖拽中到点等松手再入睡。
- 双击用平台点击计数：双击打开页面；第一击的 `React` 可以保留，不为它加 300 ms 延迟（桌面上没有与双击竞争的其它单击动作）。
- 无键盘交互；可访问名复用 `MyJiuMi.Cat.AutomationName`，提示文本可被读屏软件读到。

### 9. 边界、裁切与遮挡

- 页面房间照旧裁切；拖出时的临时猫层只受主窗口裁切。桌面窗不受主窗口裁切，也不进入任务栏与 Alt+Tab。
- 桌面窗始终置顶：会盖住普通窗口，也会盖住非独占的全屏应用；独占全屏可能盖住它。v1 接受，自动让位与点击穿透仍留给 [#102](https://github.com/ZLiLiang/JiuMi/issues/102)。
- 点击/拖拽桌面猫会把桌面窗带到前台（#112 实测无解）；接受，不为它做版本分叉。
- 页面与桌面窗都只显示猫，不显示房间；两处都不出现底板、描边或背景带。

### 10. 生命周期、入口与持久化

- **不新增全局入口**：没有托盘项、设置页分区或右键菜单；桌面模式只能从「我的JiuMi」页面进入（拖出）或被最小化/隐藏触发（走出）。
- 主窗口隐藏/最小化/恢复、托盘显示/设置/退出、关闭询问框都保持现有契约；只在隐藏/最小化路径插入「先走出再隐藏」的钩子，退出路径不等待。
- 切页离开「我的JiuMi」不触发走出：猫如果在家，按现状暂停并重置；如果已经在桌面，继续留在桌面。
- `myJiuMi.x` 是唯一持久化状态：拖回与双击召唤写入；拖出、桌面拖动、桌面屏幕坐标都不写。旧 `petEnabled` / `petX` / `petY` 保持退役，不迁移。
- 新增文案键 `MyJiuMi.DesktopHint`；实现时进 `Assets/i18n/{zh-CN,en-US}.json`，不新增设置键。

### 11. 失败与降级

| 失败 | 行为 |
| --- | --- |
| 桌面窗创建失败 / 透明不可用 | 猫留在家；走出取消，隐藏/最小化照常立即执行；记 Warning，不弹窗 |
| 拖拽预览窗创建失败 / 透明不可用 | 回退到主窗口内覆盖层继续拖拽；松手提交时按「桌面窗创建失败」处理，记 Warning |
| 桌面帧加载失败 | 关闭桌面窗，猫回家；记 Warning；页面有帧就照常显示 |
| 页面帧与桌面帧都缺失 | 不显示猫，保留房间；沿用现有降级 |
| 设置写入失败 | 记 Warning，内存位置继续生效；下次拖回/召唤重试 |
| 走回时页面不可见 | 桌面窗保持在原位置并夹回工作区；不强行切页 |
| 显示器移除 / DPI 变化 | 夹回最近工作区，按新缩放重绘；不写设置 |
| 走出被取消（退出、页面切走） | 取消迁移；退出直接关窗，切页则猫回家并按现状暂停 |

### 12. 分层与测试缝

- **Application（纯逻辑）**：`MyJiuMiPresenceMachine`（迁移与守卫）、`MyJiuMiTransitionRules`（48 DIP 提交阈值、房间投影、走回入口侧、目标 X、工作区夹取）、现有 `MyJiuMiStateMachine` 与动画清单。
- **UI**：`MyJiuMiSession`（会话、共享帧缓存、计时器、宿主协调）、`MyJiuMiView`（家庭宿主）、`MyJiuMiDesktopWindow`（桌面宿主）、拖出覆盖层与主窗口可见性/外壳钩子。
- **Infrastructure**：不新增服务；`ISettingsStore` 继续只承载 `myJiuMi.x`。
- **测试**：`JiuMi.Application.Tests` 覆盖 presence 迁移与守卫、提交阈值、投影/夹取、走回入口侧、失败回退；现有状态机测试保持。UI 用实机验收，不新建 UI 测试项目。
- **Spike**：跨窗口连续拖出与无焦点宿主；本版不阻塞桌面模式。

## 为什么是双宿主

- **单渲染器**会让猫变成一个始终置顶的窗口，即使在页面里也浮在主窗口之上：它会越过内容岛裁切、盖住关闭询问框与 InfoBar，页面模式也被迫依赖一个顶层窗口。这会把 v1 的页面宿主、滚动与切页动效一起改写。
- **全屏透明层**要把猫放进一个覆盖屏幕、可点击穿透的窗口：命中测试、焦点、多屏/DPI、功耗与「永远在最上层」都要重新处理，成本远超一只 160 px 的宠物。
- **双宿主**只新增一个小窗口和一套交接规则；页面照旧，桌面窗只在需要时存在。共享会话保证状态与帧序不分叉。代价是交接协调与两套渲染，这是本 ADR 的主要成本。

## 为什么是释放提交，而不是连续拖出

跨窗口拖拽需要在一个窗口按住指针、再把同一个手势交给另一个 `HWND`。Avalonia 的 `PointerCapture` 不跨窗口；要连续，就得在新窗口下用 Win32 捕获、轮询按键并伪造按下状态，还要处理拖拽中窗口创建/销毁与 DPI 切换。释放提交只需要在页面窗口里完成一次拖拽，再按松手屏幕点创建桌面窗：行为确定、可单测，也不依赖未验证的 Win32 技巧。连续拖出作为 spike 另行评估，成功后再升级交互动效，不改本 ADR 的宿主与持久化契约。

2026-11-13 补充：页面窗口持有捕获期间提前显示的拖拽预览窗由页面窗口驱动位置，输入与捕获不转移；它只消除猫在主窗口边缘的消失，不等于把拖拽手势交给桌面窗，也不改变释放提交。

## 备选与取舍

| 备选 | 为什么没选 |
| --- | --- |
| 单渲染器：一个置顶窗在页面与桌面共用 | 页面猫会浮在所有内容之上，裁切、弹窗与切页动效都要重写 |
| 全屏透明层承载两种模式 | 点击穿透、焦点、多屏/DPI 与功耗成本过高 |
| 连续拖出（按住跨窗口） | 指针捕获不能跨 HWND；先 spike，不阻塞本版 |
| 桌面模式持久化，重启回到桌面 | owner 确认「页面是家」；避免升级后默认出现置顶猫，也不新增设置键 |
| 恢复托盘/设置里的全局入口 | v1 已删除；页面本身足以作为入口 |
| 桌面右键菜单（回页面/设置/隐藏） | 与「简化交互」冲突，多一套菜单与文案 |
| 桌面自主闲逛 | 桌面空间没有房间边界与落点语义，先不做 |
| 桌面窗也用 200 DIP | 偏离 #122 已定的 160×160；160 已够清晰，也保持旧窗口行为 |
| 走出时无限等待猫走到边缘 | 可能拖住隐藏数秒；用 900 ms 上限与当前位置交接 |
| 走出时拦截系统最小化补播动画 | 需要还原再最小化，闪烁且脆弱；接受最小化路径的 150 ms 淡入 |
| 保存桌面屏幕坐标 | 重启回页面，坐标只服务本次会话；避免无意义设置 churn |
| 交接时新增专用美术帧 | 走路/拖拽帧已够用；先冻结美术，不为交接过早加帧 |

## 后果

**正面**

- 猫有了明确的「家」与双向路径：拖出、走出、拖回、召唤各有确定触发与回退。
- 页面模式与 v1 不变；桌面窗懒创建、回家即关，不留下常驻隐藏窗口。
- 共享状态机与帧缓存，睡眠、眨眼与帧序不会在两套宿主里分叉。
- 不新增设置键与全局入口，重新引入的复杂度被限制在一个会话协调对象和一个小窗口里。

**负面（明确接受的代价）**

- 拖出是松手提交，不是按住连续拖拽；连续手感要等 spike。
- 页面 200 DIP 与桌面 160 DIP 之间有一次可见缩放；交接帧必须对齐底边中心。
- 最小化路径看不到走路，只有 150 ms 淡入；隐藏路径最多延迟 900 ms。
- 置顶宠物会盖住全屏应用，点击会抢焦点；这是 #112 已确认、本版接受的限制。
- 页面在猫离家时是空房间，需要一行提示解释；多一个文案键。
- 多一个 UI 会话对象与外壳隐藏/最小化钩子，测试缝从“一个页面”扩到一个会话。

**中性**

- 无声音、无托盘入口、无设置项、无右键菜单。
- Win10/Win11 共用同一套窗口与交接逻辑；Win11 的实际观感按手动清单确认。
- 手机/平板与跨平台分发不在本 ADR 内。
