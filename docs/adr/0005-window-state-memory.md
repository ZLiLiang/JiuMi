# ADR-0005 窗口状态：只记导航栏展开，不记窗口几何

- 状态：已接受
- 日期：2026-10-18
- 来源：地图 #1；决议 #16；落笔 #16

## 背景

桌面应用的默认期待是「关掉再开，窗口还在原地、还是那个大小」。JiuMi 偏偏是便携优先：整个程序目录可能被拷到 U 盘、共享盘或另一台机器上运行，`settings.json` 跟着目录走。

[ADR-0001](./0001-settings-persistence.md) 把「语言、主题、窗口偏好」一起划进了这份设置。于是问题变成：窗口状态里哪些真的该进这份便携配置？#7 已经定了启动总是显示主窗口，排除了「记住最小化到托盘」。

## 决策

1. **只持久化一比特**：导航栏是展开还是收起，键为顶层 `navExpanded`（boolean，缺省 `true`）。
2. **窗口几何一律不记**：尺寸、位置、最大化状态与还原尺寸都不入配置；每次启动按 1200 × 760 打开，位置由系统决定。
3. **只在主窗口关闭时写一次**；点展开/收起按钮立即改变界面，但不触发写盘。
4. **关闭时写失败静默**：记一条不带 `code` 的 Warning 日志（操作 `Settings.SaveOnExit`），不进详情缓冲、不弹 InfoBar。
5. **不做「重置窗口布局」入口**；不新增 `window` 对象，`schemaVersion` 保持 `1`。

## 为什么只记一比特

要先分清两类状态：

- **用户偏好**：跟着人走。换台机器、换个显示器，它依然该生效。语言、主题、导航栏展开态属这类。
- **机器状态**：只对产生它的那台机器有意义。窗口位置与尺寸属这类——换一块屏幕、改一次缩放、拔掉副屏，记下的数字就可能落在屏幕外或看起来被压扁。

把机器状态塞进便携配置，代价不是「多几个键」，而是要配一整套夹取逻辑：枚举显示器工作区、处理 DPI 缩放换算、显示器消失时回退、尺寸小于最小值时钳制、最大化与还原尺寸的分离。这套逻辑要一直维护，换来的是「省用户一次拖拽」。

而 `navExpanded` 恰好相反：跨机器有意义，用户每次启动都会看到，值又只有一比特。它值得记。

## 为什么连最大化也不记

只记「是否最大化」而不记尺寸，会组合出一个怪状态：用户把窗口拉到全屏关闭，下次启动恢复为最大化，但还原尺寸永远是 1200 × 760——用户只记住「我上次是全屏」，却得到一个与印象不符的还原结果。要么整套几何一起记，要么一起不记；既然几何的代价不成立，最大化也不单列。

## 为什么放在顶层，而不是 `window` 对象

它是 UI 偏好，不是窗口几何。造一个 `window` 容器会向内暗示「里面还有尺寸和位置」，而实际上没有。

将来真要补窗口几何，那是**纯增量**：新增 `window` 对象，缺键补默认即可生效，不需要动 `schemaVersion`。所以现在不必为它预留容器。

## 为什么只在关闭时写

拖动与缩放每一帧都在产生变化。节流写会把「整文件原子写」变成持续的高频磁盘动作，还会扩大「用户运行中手改 `settings.json`、下一次自动写把改动覆盖」的窗口——而这个覆盖是静默的（未知键写时丢弃、最后写入者胜）。

导航栏状态不是必须精确到崩溃前一刻的数据：丢一次，下次启动按缺省展开，代价可接受。退出时一次写入，也就不需要任何额外的写入调度逻辑。

## 为什么退出时写失败是静默的

#2 的契约是「保存失败必须可见」，但它针对的是**用户主动修改的设置**：用户点了语言、看到界面变了，就有权知道这次改动有没有留下。导航栏展开态不是这样的设置——用户点的是导航栏按钮，不是设置项。

更关键的是时机：失败发生在退出路径上，窗口正在关闭，提示没有地方展示、也没有用户动作可承接。给它一条不带 `code` 的 Warning 日志，排障时看得到，又不会进详情缓冲、不会弹 InfoBar——可诊断性与「不打扰」两边都成立。

## 备选与取舍

| 备选 | 为什么没选 |
| --- | --- |
| 记完整几何（尺寸 + 位置 + 最大化 + 还原尺寸） | 需要显示器枚举、工作区夹取、DPI 换算与显示器消失处理；便携目录跨机器时位置常失效 |
| 只记最大化，不记尺寸 | 与固定的 1200 × 760 组合出「记住最大化、还原却总是默认尺寸」的怪状态 |
| 独立的 `window.json` | 只剩一比特，多一个文件、多一套损坏与回滚契约，零收益 |
| 变化后节流写 | 高频整文件原子写，且放大运行中手改被覆盖的窗口 |
| 退出写入失败时弹提示 | 退出路径上用户无从处理，且与 #2 的契约边界（用户主动修改）不符 |
| 提供「重置窗口布局」入口 | 只有一比特，导航栏顶部的展开/收起按钮随时能切回 |

## 后果

**正面**

- 配置契约几乎不变：一个布尔键，`schemaVersion` 不动。
- 不存在「拷到别的机器就失效」的状态，也就不需要夹取、DPI 换算与显示器消失处理。
- 没有高频写入，也没有「自动写覆盖手改」的新窗口。

**负面（明确接受的代价）**

- 每次启动都是 1200 × 760：在 4K 或超宽屏上偏小，用户每次都得手动放大。
- 上次最大化的用户，重开回到普通窗口。
- 崩溃退出会丢掉展开态（只在关闭时写）。

**中性**

- 界面上「点按钮立即生效」与「退出时才落盘」不同步；这是有意的，且对用户不可见。
