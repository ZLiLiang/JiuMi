# 2026-11-14 #94 抓包会话记录

## 结论

本轮完成了 MITM 原型的搭建与冒烟，但**没有执行微信视频抓包**：用户在开始前要求
把工作保存为云端研究分支，留到后续会话继续。系统代理与证书已清理。

## 已完成

- 阅读旧 `ZLiLiang/JiumiTool` 的 `JiumiTool2` 分支：
  - `HttpsProxyService`：Titanium 3.2.0，`127.0.0.1:9743` 起代理，只对
    `channels.weixin.qq.com` / `finder.video.qq.com` 解密，向 HTML 注入
    `InjectionScript.js`；
  - 注入脚本包装 `WeixinJSBridge.invoke`，`err_msg` 含 `H5ExtTransfer:ok` 时取
    `object.object_desc.media[0]`，POST 回代理端口；
  - 旧下载器只对首块前 131072 字节做 XOR，与票面「逐字节 XOR」不一致。
- 新建一次性 net10 控制台原型 `WeChatSpike`：
  - Titanium 7.0.27；代理只绑定 `127.0.0.1` 随机端口；
  - 独立本地回传 listener（TCP，`127.0.0.1` 随机端口 + 随机路径），不再复用代理端口；
  - 系统 HTTPS 代理切换与快照/还原；CurrentUser 根证书 `JiumiSpike`；
  - 注入脚本在旧 H5ExtTransfer 基础上增加 `invoke`、`fetch`、`XHR`、`resource`
    四类观察，用于判断视频号是否走同一 H5/桥。
- 冒烟测试（`--no-system-proxy`）：
  - `curl -x http://127.0.0.1:<port> -k https://channels.weixin.qq.com/` 返回 200；
  - 响应 HTML 含注入标记，日志记录 `INJECT ... script=6469B`；
  - 说明代理解密、HTML 注入、随机端口 listener 均可用。
- 正式会话准备：
  - 系统 HTTPS 代理切到 `127.0.0.1:64606`，HTTP 仍保留 `127.0.0.1:7897`；
  - CurrentUser 证书信任弹窗（`#32770`「安全警告」）通过 `BM_CLICK` 确认「是(Y)」；
  - 微信已启动，但用户要求在打开视频前暂停，未产生目标流量。

## 清理结果

- 停止方式：创建 `logs/STOP`，进程正常退出，端口释放。
- 系统代理已还原：
  - `ProxyEnable=1`、`ProxyServer=127.0.0.1:7897`、原 `ProxyOverride` 保留、
    `AutoConfigURL` 为空。
- 临时根证书 `CN=JiumiSpike` 已从 `CurrentUser\Root` 与 `CurrentUser\My` 删除
  （程序的自动清理未删干净，已手工按指纹删除并复核为空）。
- WeChat 进程保持运行，未改动其登录状态。

## 下次开始前

1. 先确认 `CurrentUser` 下没有残留 `CN=JiumiSpike` 证书，系统代理仍是用户原配置。
2. 重新运行 `dotnet run -c Release -- --minutes=25`，批准证书弹窗。
3. 按 README 的续做清单依次抓聊天分享视频与视频号视频。
4. 如果微信完全没有走代理，优先检查：
   - XWeb 是否忽略 WinINet 系统代理（可能需要 WinHTTP，需管理员）；
   - 是否走 QUIC/HTTP3；
   - XWeb 是否用自带证书库（CurrentUser 根证书可能不生效）。
5. 完成后回填 #94；go 时写 ADR-0013，no-go 时把 #68 转 `needs-info`。
